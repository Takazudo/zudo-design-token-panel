zdtp fix4 prototype — container-query responsive header/tabs
The panel shell becomes a named query container (container: tokenpanel / inline-size). Three container breakpoints drive the mobile-style degradation — the viewport is never consulted, so a narrow panel on a wide desktop screen degrades identically. Recommended variant: A — kebab menu + scrollable tabs (below).
Live resizable demo (drag the bottom-right corner)
≥480px: full header links · <480px: links collapse to the ⋯ kebab · <380px: DENSITY label hides · <300px: slider narrows. Tabs scroll horizontally with a right-edge fade whenever they overflow (any width).
Pinned widths — variant A (recommended)
Why not variant B (two-row wrap)?
Wrapping the action links onto a second header row keeps every action visible, but costs 24–28px of vertical space in a panel that is already height-constrained, gives the drag-to-move header an awkward tall hit area, and still breaks below ~300px (four links + title cannot fit two columns). The kebab pattern keeps the header a single 36px row at every width — matching what the resize interaction promises: the panel chrome never reflows vertically. Rendered below for comparison at 340px.

Implementation notes (for the sub-issue)
Files: packages/zdtp/src/panel.tsx (kebab button + popover + open state), packages/zdtp/src/styles/panel.css (container declaration + 3 @container blocks + tab overflow).

1. .tokenpanel-shell { container: tokenpanel / inline-size; } — shell width is always explicit (inline style), so inline-size containment is safe.
2. Kebab button = <div role="button" tabIndex={0}> per chrome-button policy; popover = a PLAIN popover of ordinary action RoleButtons — NOT role="menu"/menuitem (that ARIA contract demands arrow-key nav + focus management, and RoleButton hardcodes role="button"). Follow the existing gear-settings popover's close wiring in panel.tsx (outside-click + Escape). aria-expanded on the trigger. Close/reset the open state when an action fires or the panel crosses back to the wide layout. (This page's demo markup still says role="menu" — the plan/sub-issue text supersedes it.)
3. The kebab renders ALWAYS (both widths) — visibility is pure CSS via @container, so no JS width tracking is needed and SSR/hydration is width-agnostic.
4. Tabs overflow: overflow-x:auto + hidden scrollbar + right-edge fade mask when scrollable (.has-overflow toggled by a ResizeObserver on the tabs strip + its scroll events — a panel grip resize does NOT emit window.resize, so a window listener would miss it).
5. Header/tab labels get white-space:nowrap so intermediate widths never mid-word wrap.
6. Breakpoints: 480 / 380 / 300 (px, container width). Tune ±20px at implementation time if the real font metrics differ.
7. Browser floor: container queries are Baseline 2023 (Safari 16+). The panel is a dev tool for developers on evergreen browsers — acceptable. Un-queried base styles (wide layout) are the fallback.
